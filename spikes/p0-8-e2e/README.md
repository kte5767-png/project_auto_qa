# P0-8 브라우저 E2E 스파이크

앱을 리모컨 키로 조작하면서 두 가지를 한 번에 확인합니다.

- **화면설계서대로 움직이는가** (D-036 ①): 키를 누르기 전 포커스가 있던 콜아웃의 키 동작 문장을 이동 지도로 해석해 기대 포커스를 코드로 계산하고, 실제 포커스와 비교합니다 (`{ "focus": "@spec" }`).
- **화면이 조건대로인가** (D-036 ③, D-037): 포커스 위치, 글자가 있는지, 개수 상한, 정해진 문구를 코드로 판정하고 단계 판정을 모읍니다. 확인하지 않는 조건은 Pass를 막지 않고 설명에 적습니다.

드라이버 인터페이스만 쓰므로 같은 흐름이 실기기 드라이버에서도 돕니다 (D-027). 페이지 스크립트(`@auto-qa/focus`의 `observeTargets`)는 ES2017 문법이라 webOS 5.x에서도 돕니다.

## 실행

```bash
# 샘플 앱 (pnpm sample:dev 로 띄운 뒤)
pnpm spike:e2e spikes/p0-8-e2e/scenario.sample.json
pnpm spike:e2e spikes/p0-8-e2e/scenario.sample.json --url "http://localhost:5173/?defects=D11,D12"

# 실제 앱 (다른 창에서 앱을 띄운 뒤). 화면설계서 내보내기 파일·폴더를 --spec 으로
pnpm spike:e2e spikes/p0-8-e2e/scenario.local.json --spec spikes/p0-8-e2e/spec --headed
```

| 옵션       | 설명                                                                                                                                                                                                                               |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--url`    | 시나리오의 `url` 대신 쓸 주소                                                                                                                                                                                                      |
| `--spec`   | 화면설계서 내보내기 JSON 파일 또는 폴더 (여러 번 가능). 없으면 `@spec` 조건은 확인 불가                                                                                                                                            |
| `--headed` | 브라우저 창을 띄워 진행을 봅니다. 키마다 멈추고(`--slow`), 1920×1080 화면이 모니터에 다 보이게 창 배율을 맞춥니다(`--scale`)                                                                                                       |
| `--slow`   | 키마다 멈추는 시간(ms). 사람이 따라보기 위한 것이며 판정과 무관합니다(판정은 안정화 대기 후 관찰). 기본: `--headed`면 800, 아니면 0. 시간에 따라 바뀌는 동작(예: 포커스 2초 뒤 Marquee)은 멈춤 때문에 화면이 달라 보일 수 있습니다 |
| `--scale`  | `--headed` 창 배율. `auto`(기본)는 창을 잠깐 띄워 모니터 크기·Windows 배율을 읽고 맞춥니다(예: 1920×1080 노트북 + 배율 150% → 0.85). 창에 그리는 크기만 바뀌고 페이지 레이아웃·캡처(1920×1080)는 그대로입니다                      |
| `--out`    | 결과 폴더 (기본 `spikes/p0-8-e2e/out/<시각>/`)                                                                                                                                                                                     |

결과: `report.md`(단계 표 = 엑셀에 쓸 `자동 판정`·`판정 설명`·`판정 근거`), `result.json`, 단계별 캡처 `step-*.png`, `entry.png`.

## 시나리오 (`auto-qa/e2e-scenario`)

실제 앱용 시나리오는 회사 앱 정보(선택자·화면설계서 번호)가 들어 있으므로 `*.local.json`으로 두고 커밋하지 않습니다.

- `elements`: 사람이 정한 콜아웃 ↔ 앱 요소 대응 (설계 7.11 ②). `selector`(CSS, `:has()` 금지), `items`(목록 항목), `textIncludes`, `callout`(`"4.2#1"` = 4.2 화면 ①), `names`(화면설계서 문장에서 부르는 이름, 예: `GNB`).
- `entry`: 시작 화면까지 가는 길. `waitFocus`(앱에 포커스가 생길 때까지), `waitFor`(요소가 보일 때까지), `press` + `until`(그 요소에 갈 때까지 같은 키, 안 되면 `else` 키).
- `steps[].checks`
  - `{ "focus": "검색창" }` / `{ "focus": "추천 검색어", "item": 0 }`: 포커스 위치
  - `{ "focus": "@spec" }`: 이 단계의 키마다 화면설계서 이동 지도와 비교
  - `{ "present": "추천 검색어 제목" }`: 바뀔 수 있는 글자 — 있는지만 (D-036 ②)
  - `{ "count": "추천 검색어", "max": 5 }`: 개수 상한
  - `{ "text": "검색창", "equals": "…" }`: 정해진 문구 — UX 문장에 적힌 문구이거나 사람이 "정확히 비교"로 지정한 것만
  - `{ "unchecked": "…" }`: 화면으로 확인하지 않는 조건 (판정 설명의 "확인하지 않은 조건")
- `aliases`: 화면설계서 이름 ↔ 문장 속 이름 (예: `{ "Recommended Keywords": ["추천 검색어"] }`)
- `timing`: `readyTimeoutMs`(기본 20000), `pollMs`(기본 200). 고정 sleep은 쓰지 않고 키마다 안정화 대기 + 조건 대기만 합니다.

## `@spec` 판정 규칙

- 키를 누르기 전 포커스가 `callout`이 지정된 요소에 있어야 합니다. 없으면 확인 불가로 남깁니다.
- 기대 위치: 다른 콜아웃 첫 항목(`move:N:first`), 이동 이력(`+memory`: 그 목록에서 마지막으로 있던 항목, 없으면 첫 항목), 같은 목록 다음·이전(`next`·`prev`), 동작 없음(제자리), 화면 밖(`leave:GNB` → `names`가 맞는 요소).
- 목록 콜아웃에서 반대 방향 키가 "다음 항목"이면, 목록 끝이 아닐 때는 이전 항목으로 봅니다(화면설계서가 "[◀]: GNB 확장"처럼 첫 항목에서의 동작만 적는 경우).
- 이름으로 정하지 못해 키 방향으로 추정한 대상은 Pass로 확정하지 않고 확인 필요로 둡니다.

## TC 실행 (`pnpm spike:tc-run`)

TC 엑셀의 자동 대상 단계(화면설계서 번호 `--screen`, 기본 4 = 4.x)를 앱에서 실행하고, **그 TC 파일에 양식 그대로** 결과를 씁니다(D-040). 열을 추가하지 않습니다.

| 판정                                    | P/F 열 (그 파일의 드롭다운 값) | 이유 열 (`Issue Detail` 등)            |
| --------------------------------------- | ------------------------------ | -------------------------------------- |
| Pass                                    | Passed                         | 확인하지 않은 조건이 있을 때만 적음    |
| Fail                                    | Failed                         | Fail 이유                              |
| 확인 필요 (애매함)                      | Passed                         | `[확인 필요]` + 이유, 칸에 연한 노란색 |
| 확인한 조건 없음·미실행·음성 안내(보류) | 비워 둠                        | 비워 둠                                |

- 쓰기 전에 같은 폴더에 백업을 남깁니다: `<이름>.before-auto-qa-<시각>.xlsx`. 바뀌는 칸이 없으면 백업도 만들지 않습니다.
- 이미 값이 있는 칸은 건드리지 않고 알려 줍니다. 다시 검수해 덮어쓰려면 `--overwrite`.
- 엑셀에서 TC 파일을 연 채로 실행하면 쓰지 못합니다(원본은 그대로). 닫고 다시 실행하세요.
- 조건별 근거·캡처·확인 필요 목록은 `report.md`에 있습니다.

```bash
pnpm spike:tc-run <TC.xlsx> --profile spikes/p0-8-e2e/profile.local.json --spec spikes/p0-8-e2e/spec [--only Search!9,Search!10] [--headed]
```

TC 한 줄은 콜아웃 하나의 사양입니다. **같은 화면의 단계들은 앱을 한 번만 열고**(D-038), 키를 누른 뒤에는 키로 목표에 돌아옵니다.

- 돌아오기: 그 화면이 안 보이거나 다른 화면(팝업 등)에 포커스가 있으면 BACK, 공통 요소(GNB 등)에 있으면 그 요소의 `exit` 키
- 목표 콜아웃 첫 항목까지: 이동 지도로 길을 계산해 따라가고, 길이 없거나 콜아웃 밖이면 목표 쪽 방향키 한 번씩(목표 지향 탐색, D-024), 목록 안이면 "이전" 키로 첫 항목까지. 같은 자리를 다시 만나면 멈춤
- 그래도 못 가면 그때만 앱을 다시 엽니다(새 브라우저 컨텍스트). 길이 아예 없는 목표는 한 번만 시도하고 확인 필요로 남깁니다
- 마지막에 "앱을 연 횟수"를 출력합니다

| 조건 종류 (D-037)                                | 확인 방법                                                                                                                                                                                                  |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 있는지만·타이틀·아이콘                           | 콜아웃 요소(타이틀은 `title` 선택자)가 보이고 글자가 있는지. 아이콘은 보이는지만                                                                                                                           |
| 최대 N개                                         | 보이는 항목 수. "OTA 콘텐츠는 최대 5개"처럼 콜아웃이 아닌 일부 종류가 주어이면 확인 불가                                                                                                                   |
| 정해진 문구(따옴표)                              | 요소·항목·타이틀 글자 중 같은 것이 있는지                                                                                                                                                                  |
| 포커스 (진입 시·첫 번째 항목)                    | 그 화면에 들어왔을 때 포커스가 그 콜아웃(첫 항목)에 있었는지                                                                                                                                               |
| 말줄임                                           | 칸을 넘치는 글자가 모두 `text-overflow: ellipsis`인지. 넘치는 글자가 없으면 확인 불가                                                                                                                      |
| 키 동작 `[▲]…`                                   | 목표 콜아웃 첫 항목으로 간 뒤 키 하나를 누르고 화면설계서와 비교                                                                                                                                           |
| 선택 시 (화면 전환·나타나는 것·포커스·선택 불가) | 목표에서 OK 한 번. 문장이 가리키는 화면(`#4.2.` 번호 또는 프로필 화면 `names`, "(… 참고)" 괄호는 뺌)이 새로 보이거나 포커스가 그 화면으로 옮겨 갔는지. "Default 포커스로 이동"은 진입 때의 기본 포커스인지 |
| 가상 키보드                                      | 확인 불가 (브라우저에는 VKB가 없음, TV에서 확인)                                                                                                                                                           |
| Marquee·조작 결과·미노출, AI 대상 서술           | 아직 자동 확인 없음 → 확인 필요                                                                                                                                                                            |

결과: TC 파일(P/F·이유 칸)과 백업, `out/tc-<시각>/`에 `report.md`(확인 필요 목록 포함), `result.json`, 단계별 캡처.

### 앱 프로필 (`auto-qa/app-profile`, `*.local.json`)

- `elements`: 공통 요소 (화면 밖 대상 `GNB` 등, `names`로 화면설계서 문장과 대응, `exit`는 거기서 화면으로 돌아오는 키)
- `screens["4.2"]`: `detect`(그 화면이 떠 있는지 볼 선택자), `names`(화면 전환 문장 속 이름), `from`(먼저 갈 화면), `entry`(진입 단계, 요소 이름은 공통 이름·`#N`·`4.2#5`), `callouts`(번호 → `selector`·`items`·`title`·`name`)
- 프로필에 없는 화면·콜아웃은 미실행으로 남기고 이유를 적습니다.

### 정확도 (사람 판정과 비교)

사람이 P/F를 적은 **다른 파일**(같은 TC 양식의 QA 결과 보고서 등)과 비교합니다. 실행할 때 `--truth`를 함께 주거나, 실행 없이 지난 결과로 비교합니다. 실행할 TC 파일 자체는 정답으로 쓸 수 없습니다(결과를 거기에 쓰므로).

```bash
pnpm spike:tc-run --score spikes/p0-8-e2e/out/tc-<시각>/result.json --truth <QA 결과 보고서.xlsx>
```

일치율은 자동으로 Pass/Fail을 낸 단계 중 사람과 같은 비율이고, 틀린 Pass(사람 Fail인데 자동 Pass)를 따로 셉니다. 확인 필요·미실행 단계 수도 함께 보여 줍니다.
