# 사용자 UI 1차 (`@auto-qa/web`)

UX Pilot 시안(대시보드 · 새 검수 · 검수 중 · 결과)을 판넬 톤으로 옮긴 화면입니다 (D-041, 기획 고정 D-044).
로컬 PC에서만 열립니다(127.0.0.1:8093). 회사 자료는 이 PC 밖으로 나가지 않습니다.

## 실행

```powershell
# 대상 앱은 다른 창에서 (예: lg_travel_service_app → npm run serve, localhost:8091)
pnpm web            # http://127.0.0.1:8093
```

- **새 검수**: TC 엑셀 경로(이 PC의 절대 경로), UX 시나리오(화면설계서) 폴더, 앱 프로필, 앱 주소를 넣고 시작합니다. 내부적으로 `spikes/p0-8-e2e/tc.ts`를 실행합니다(명령줄 `pnpm spike:tc-run`과 같음). 입력값은 `spikes/p0-8-e2e/out/web-settings.json`에 저장돼 다음에 그대로 채워집니다.
- **검수 중**: 서버가 바뀌는 즉시 밀어 주는 방식(SSE, `/api/stream`)으로 받습니다. 끊기면 브라우저가 1초 뒤 다시 잇고, 이으면 지금 상태 전체를 다시 받습니다.
  - 진행률·단계 목록(지금 단계를 따라 내려감)·실패·확인 필요(바로 확인)
  - 지금 단계 안에서 **하는 일**(앱 여는 중, 화면으로 들어가는 중, 목표 찾아가는 중, 키 ▼ 동작 확인 중, 선택(OK) 결과 확인 중, 처음 화면으로 되돌리는 중)과 이 단계 경과 시간
  - **리모컨 입력**: 지금 단계에서 누른 키·동작이 누르는 즉시 쌓이고, 마지막 포커스 위치를 보여 줍니다
  - **실시간 앱 화면**: 실행 엔진이 브라우저 화면을 받아(`live.jpg`, 앱 DOM을 건드리지 않는 CDP screencast) 바뀌는 즉시 보여 줍니다. 실행이 끝나면 마지막 단계 캡처를 보여 줍니다
  - 실행 로그(단계 시작·Pass·Fail·확인 필요 색 구분, 위로 올려 읽는 중이면 따라 내려가지 않음), 연결 상태, 10초 넘게 갱신이 없으면 마지막 갱신 시각
  - 시작 직후(TC 읽기·브라우저 열기)에는 "준비 중"으로 보이고 이전 실행을 보여 주지 않습니다. 중지·오류로 단계 도중에 끝나면 "중지됨"·"중간에 끝남"으로 보입니다
  - **중지**는 검수 프로세스와 그 아래 브라우저까지 함께 끝냅니다 (Windows는 `taskkill /T /F`)
- **결과**: 통과·실패·확인 필요·미실행, 확인 필요 항목 확정(통과/실패, `decisions.json`에 저장 — TC 파일은 바꾸지 않음), 단계 격자, 실패 항목, 단계 상세(앱 캡처, 조건별 판정, Issue Detail에 쓴 설명, 리모컨 입력 경로), 결과 TC 엑셀 내려받기.
- 명령줄로 실행한 결과도 `spikes/p0-8-e2e/out/tc-*`에 있으면 그대로 보입니다.

## 구조

- `server/api.ts`: Vite 개발 서버 안의 로컬 API (`/api/runs`, `/api/run`, `/api/stream`, `/api/live`, `/api/stop`, 캡처·실시간 화면·TC 파일 제공). 실행 폴더 이름·파일 이름만 받아 경로 밖으로 나가지 않습니다. 화면을 보는 사람이 있을 때만 지금 실행의 `progress.json`·`live.jpg`가 바뀌었는지 150ms마다 확인해 보냅니다.
- `server/stream.ts`: SSE 이벤트·로그 줄 나누기·지금 볼 실행 고르기·중간에 끝난 진행 파일 고치기 (순수 함수, 테스트 있음).
- `src/live.ts`·`src/useLiveStream.ts`: 받은 이벤트를 모으는 상태(순수 함수, 테스트 있음)와 EventSource 연결.
- `src/pages/*`: 화면 4개. `src/styles.css`: 판넬 색(네이비 #0B2559, 블루 #1E4C8F, 라이트 #DCE6F3)·글꼴(Paperlogy, Pretendard).
