# P0-8 브라우저 E2E 스파이크

앱을 리모컨 키로 조작하면서 두 가지를 한 번에 확인합니다.

- **화면설계서대로 움직이는가** (D-036 ①): 키를 누르기 전 포커스가 있던 콜아웃의 키 동작 문장을 이동 지도로 해석해 기대 포커스를 코드로 계산하고, 실제 포커스와 비교합니다 (`{ "focus": "@spec" }`).
- **화면이 조건대로인가** (D-036 ③, D-037): 포커스 위치, 글자가 있는지, 개수 상한, 정해진 문구를 코드로 판정하고 단계 판정을 모읍니다. 확인하지 않는 조건은 Pass를 막지 않고 설명에 적습니다.

드라이버 인터페이스만 쓰므로 같은 흐름이 실기기 드라이버에서도 돕니다 (D-027). 페이지 스크립트(`@auto-qa/focus`의 `observeTargets`)는 ES2017 문법이라 webOS 5.x에서도 돕니다.

## 실행

```bash
# 샘플 앱 (pnpm sample:dev 로 띄운 뒤)
pnpm spike:e2e spikes/p0-8-e2e/scenario.sample.json
pnpm spike:e2e spikes/p0-8-e2e/scenario.sample.json --url "http://localhost:5173/?defects=D11,D12"

# 실제 앱 (다른 창에서 앱을 띄운 뒤). 화면설계서 내보내기 파일·폴더를 --spec 으로
pnpm spike:e2e spikes/p0-8-e2e/scenario.local.json --spec spikes/p0-8-e2e/spec --headed
```

| 옵션       | 설명                                                                                    |
| ---------- | --------------------------------------------------------------------------------------- |
| `--url`    | 시나리오의 `url` 대신 쓸 주소                                                           |
| `--spec`   | 화면설계서 내보내기 JSON 파일 또는 폴더 (여러 번 가능). 없으면 `@spec` 조건은 확인 불가 |
| `--headed` | 브라우저 창을 띄워 진행을 봅니다                                                        |
| `--out`    | 결과 폴더 (기본 `spikes/p0-8-e2e/out/<시각>/`)                                          |

결과: `report.md`(단계 표 = 엑셀에 쓸 `자동 판정`·`판정 설명`·`판정 근거`), `result.json`, 단계별 캡처 `step-*.png`, `entry.png`.

## 시나리오 (`auto-qa/e2e-scenario`)

실제 앱용 시나리오는 회사 앱 정보(선택자·화면설계서 번호)가 들어 있으므로 `*.local.json`으로 두고 커밋하지 않습니다.

- `elements`: 사람이 정한 콜아웃 ↔ 앱 요소 대응 (설계 7.11 ②). `selector`(CSS, `:has()` 금지), `items`(목록 항목), `textIncludes`, `callout`(`"4.2#1"` = 4.2 화면 ①), `names`(화면설계서 문장에서 부르는 이름, 예: `GNB`).
- `entry`: 시작 화면까지 가는 길. `waitFocus`(앱에 포커스가 생길 때까지), `waitFor`(요소가 보일 때까지), `press` + `until`(그 요소에 갈 때까지 같은 키, 안 되면 `else` 키).
- `steps[].checks`
  - `{ "focus": "검색창" }` / `{ "focus": "추천 검색어", "item": 0 }`: 포커스 위치
  - `{ "focus": "@spec" }`: 이 단계의 키마다 화면설계서 이동 지도와 비교
  - `{ "present": "추천 검색어 제목" }`: 바뀔 수 있는 글자 — 있는지만 (D-036 ②)
  - `{ "count": "추천 검색어", "max": 5 }`: 개수 상한
  - `{ "text": "검색창", "equals": "…" }`: 정해진 문구 — UX 문장에 적힌 문구이거나 사람이 "정확히 비교"로 지정한 것만
  - `{ "unchecked": "…" }`: 화면으로 확인하지 않는 조건 (판정 설명의 "확인하지 않은 조건")
- `aliases`: 화면설계서 이름 ↔ 문장 속 이름 (예: `{ "Recommended Keywords": ["추천 검색어"] }`)
- `timing`: `readyTimeoutMs`(기본 20000), `pollMs`(기본 200). 고정 sleep은 쓰지 않고 키마다 안정화 대기 + 조건 대기만 합니다.

## `@spec` 판정 규칙

- 키를 누르기 전 포커스가 `callout`이 지정된 요소에 있어야 합니다. 없으면 확인 불가로 남깁니다.
- 기대 위치: 다른 콜아웃 첫 항목(`move:N:first`), 이동 이력(`+memory`: 그 목록에서 마지막으로 있던 항목, 없으면 첫 항목), 같은 목록 다음·이전(`next`·`prev`), 동작 없음(제자리), 화면 밖(`leave:GNB` → `names`가 맞는 요소).
- 목록 콜아웃에서 반대 방향 키가 "다음 항목"이면, 목록 끝이 아닐 때는 이전 항목으로 봅니다(화면설계서가 "[◀]: GNB 확장"처럼 첫 항목에서의 동작만 적는 경우).
- 이름으로 정하지 못해 키 방향으로 추정한 대상은 Pass로 확정하지 않고 확인 필요로 둡니다.
